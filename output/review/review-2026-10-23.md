# Healthak review — 2026-10-23

Scope: source review of plans, Today/home UI, theme/motion, assistant orchestration, repositories, and Firestore rules. No live app visual QA or deployed-rule test. No application code changed.

## Assessment

Keep the architecture: pure Dart domain, derived macros, sealed meal entries, flattened day records, typed repositories, and proposal/confirm/undo are useful foundations. Improve the daily interaction and write reliability before adding more visual effects.

## Prioritized findings

1. **High: non-atomic assistant replacement.** `agent_tool_registry.dart:232-243` checks freshness, removes an entry, then inserts its replacement through separate transactions. Failure between writes loses the original without completing replacement. Move validation and replacement into one repository transaction.
2. **High: incomplete, non-atomic freshness validation.** `_assertFresh` at line 478 compares only item count, total kcal, and eaten state. Equal-calorie changes, slot changes, and other edits pass. Its read is also separate from the mutation. Compare a revision or complete relevant snapshot inside the write transaction.
3. **High for distribution: embedded provider key.** `ai_client.dart:20-24` supports an extractable build-time xAI key. This was an intentional personal-use exception; before distributing, use the authenticated proxy and server-controlled quotas.
4. **Medium: proxy feature mismatch.** `functions/index.js:65-67,247` still uses the read-only tool list while Dart exposes write proposals. Removing the embedded key alone will not preserve assistant capabilities. Align schemas and test proxy/direct behavior before switching.
5. **Medium: marketplace deletion rule.** `firestore.rules:49-51` combines update/delete with a `request.resource.data.authorUid` condition. Delete has no new document; split delete ownership checks from update validation. Verify with the Firestore emulator. Author updates also bypass create-time shape constraints; apply the relevant invariants on update.
6. **Medium: stream can stall.** `ai_client.dart:126,256` times out the request for headers but subsequent response-stream loops have no explicit idle/overall deadline. Add cancellation and stream deadlines.
7. **Maintenance: stale guidance.** AGENTS.md still says data/UI are unstarted and describes `lib/page/` as legacy, while new screens live there. PROGRESS contains superseded assistant behavior. Consolidate a current-state summary so agents do not follow obsolete guidance.

## UI recommendation

Today currently combines greeting, calendar, ring/legend, target summary, macro panel, meal sections, and substantial motion. The assistant entry disappears during scrolling; navigation labels appear only on selection; the central FAB has placeholder behavior on some tabs.

Propose a calm, food-focused light theme with porcelain surfaces, forest-green Arabic text, emerald actions, and small food photography. Keep a coordinated dark option. Put one consumed/target/remaining energy summary above compact macros and make meals visible sooner. Put planned totals behind an explicit view or expansion. Keep all four navigation labels visible. Make adding food and talking to the assistant stable labelled actions. Remove ambient motion and recurring arrival sweeps from the daily hot path; reserve short feedback for user actions.

`healthak-ui-concept.png` is a generated visual concept, not an implementation or verified nutrition example. Correct generated number order, macro consistency, Arabic text and RTL back navigation before building it. Built-in image generation was used with a prompt for two Arabic RTL screens: a calm light Today dashboard and a voice assistant with transcript, editable proposal, and tap confirmation.

## Voice recommendation

Reuse the existing ChatOrchestrator and tool registry. Start with short voice commands: tap microphone, show live transcript, stop, edit/send, display independent confirmation cards, tap to execute, optional spoken receipt. Keep TTS optional and add a stop-speaking action. Never infer quantities, cooked/raw state, or ambiguous foods silently.

Correct `plans/voice_agent_deferred.md`: platform speech recognition is not guaranteed offline, and the transcript-review instruction conflicts with automatic send on release. Prefer available ar-SA recognition, with user choice rather than an Egyptian-first fallback. `speech_to_text` is intended for short commands, not continuous conversations: https://pub.dev/packages/speech_to_text .

For a later conversational mode, evaluate streaming STT, LLM/tool orchestration, TTS and interruption handling through LiveKit. Keep domain mutations in the same confirmation path. Documentation: https://docs.livekit.io/agents/logic/turns/ . Do not claim Saudi quality without testing Saudi speakers, food vocabulary, quantities, mixed-language phrases and noise. Measure food/quantity/date correctness, duplicate actions, full turn latency and successful completion, not transcription alone.
